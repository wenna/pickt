# 收题、答案与界面改进建议（待确认）

日期：2026-10-26。依据：用户的两段操作视频、Demo V2.4 及原生 0.1。

此文件记录新增功能的建议，不代表云端分题、答案照片或界面改版已经实现。用户已接受“主动触发并确认后，将当前试卷页发送给免费云端接口，保留本地和手动回退”的方向；具体服务尚未开通或实际联调。个人视频和抽帧只存于被忽略的 `.local-data/`，不提交、不上传到模型或 CI。

## 观察与本轮修复

第一段视频显示原生蓝框每次拖动都会从手指落点重画，无法移动已有框，也没有大小调整手柄。代码缺少命中检测和移动/缩放模式。本轮修复该既有框选能力：框内拖动移动，拖八个手柄调整大小，框外拖动重画，整页初始框内部仍能新建，双指缩放和平移图片；遮盖模式只重画区域。

第二段视频展示了：调整整页边界 → 候选题框点击多选 → 保存数量 → 分类/答案逐题完善 → 一次保存。约 1:12 起的答案区域已有“拍照添加”和“AI 解题”入口，视频未演示其识别效果，不能据此认定准确率或公式能力。

## 路线与取舍

| 路线 | 收益 | 代价与状态 |
| --- | --- | --- |
| 全本地 | 无上传、无费用、离线使用 | Vision 文字识别不等同整题分割；公式、双栏和跨页题需要大量验证 |
| 本地核心＋可选免费云端（已接受的方向） | 可使用专门切题接口，保留手动回退 | 需个人服务账号和密钥；免费条款/可开通状态在联调时再核验；实际效果未测 |
| 电脑 OCR 服务 | 可使用 Umi-OCR、Surya、MathCraft 等已有工具 | 需电脑/局域网或自建服务；当前 Python/桌面项目不能直接当作 iOS 15.5 SDK 使用，不符合独立手机使用的首选方向 |

建议：把阿里云通义“试卷切题”作为专业分题的首个联调候选；GLM-4.6V-Flash 可作为图文/公式文字和答案草稿的候选。通用视觉模型输出坐标并不等于可靠切题，必须用测试卷核对漏题、框完整程度、多栏与图形。尚未选定或承诺任何模型的实际准确率。

官方核验（2026-10-26）：

- [阿里云产品页](https://help.aliyun.com/zh/model-studio/brief-introduction-of-edu-tutor)：明确返回题目文字和坐标；当前公测免费，各接口每账号每天 1000 次，5 QPS。公测不是永久免费承诺；账号是否能开通尚未实测。
- [智谱价目表](https://docs.bigmodel.cn/cn/guide/start/pricing)：GLM-4.6V-Flash 输入/输出标为免费；FlashX 为收费型号，不能混用或自动升级。
- [Math_Tutor_RAG](https://github.com/lii-lii321/Math_Tutor_RAG) 是 Python/Streamlit/FastAPI 项目，AI Provider 可作参考；无密钥时的模拟模式不能借用为真实识别结果。
- [wrong-notebook](https://github.com/wttwins/wrong-notebook) 是 Next.js 系统，提供兼容模型配置，可参考产品流程。
- [Umi-OCR](https://github.com/hiroi-sora/Umi-OCR)、[Surya](https://github.com/datalab-to/surya)、[MathCraft OCR](https://github.com/SakuraMathcraft/MathCraft-Models/blob/main/README_MATHCRAFT_OCR.md) 可研究文字/版面/公式处理；按其文档部署能力评估，不直接替换原生 App。

## 建议收题流程

1. 拍摄或从相册选择试卷，调整整页边界与方向。框四角可拖；多页显示页码和切换按钮。
2. 默认可手动框选。用户点击“自动分题”时选择已配置服务并确认上传当前页；不自动上传全部相册图片、历史试卷或视频。
3. 候选题框显示题号、加号/选中状态；点击任一框选择/取消，底部固定“已选 N 题 / 下一步”。可以检查全题预览、调整边界、补框/移除错误候选框，重复点击不重复添加。
4. 进入多题整理页：逐题显示题图、多个知识点、多个错因、年级/科目和答案入口；可沿用公共分类，也可直接保存后补答案。
5. 明确成功保存数量，再返回错题本或继续拍卷。识别失败、超时、额度耗尽时保留原图及已选结果并回到手动模式。

跨栏、共用题干、子题、图形和跨页题不能简单按文字框各自存题；允许用户将多个片段合并为一道题。原图/坐标与题号映射保留，不把 OCR 提取文本当作题图替代品。

## 参考答案建议：三种入口

### 1. 拍照/相册添加标准答案（优先）

- 单题：在题目整理页点“拍答案”，框选对应答案与解析，预览后关联当前题。
- 整页：扫描教材/试卷标准答案，先选对应来源试卷，再按“大题/小题号＋题干线索”给出匹配建议。重复题号、缺题号、模糊内容、合并子题进入待确认列表，不按列表顺序静默配对。
- 保存答案原图和片段，OCR/公式识别只做可编辑辅助；即使分数或几何解析转文字失败，仍可查看与打印清晰图片。
- 关联后显示“待核对”，由家长确认参考答案。教师批改过的学生作答照，也不能自动当作整道题标准答案。

### 2. 手动填写

保留当前文字入口；允许与照片并存，可稍后补充。答案为空不妨碍收题和组学生练习卷；核对时明确“缺少已确认参考答案”，不自动判对。

### 3. AI 解题建议（可选）

用户主动调用已核实免费的模型生成草稿，标明来源和待核对状态。它与教材/老师标准答案分开显示，不能自动覆盖已确认答案、自动确认练习结果或设置掌握状态。

## 资料与打印约束

- 题目截图、参考答案、孩子重做作答分开保存。建议新增版本化的参考答案记录，包含题目 ID、来源（人工文字/答案照片/AI）、确认状态、图片片段和可编辑文字。
- 原有 answer 字符串通过兼容读取迁移为人工参考答案，新增字段缺省可解码，不清库。具体 schema 与备份版本在实现前设计并验证；历史练习卷保留当时的答案快照。
- 答案照片及原图纳入完整备份和引用集合，含删除项及历史卷。恢复失败保留原资料。
- 学生卷不含答案文字/图片。家长页显示已确认答案和解析，另起 A4；双面必要时补白。答案图片跨页布局也需实际 PDF 测试。
- “拍参考答案”与练习卷中的“拍已做试卷”使用不同入口和文案。后者仍进入批改草稿，逐题核对后确认入库，打印不等于完成。

## UI 方向（建议）

保留拾题清新蓝色、三底栏和系统字体。参考视频的“大图画布＋可拖边框/候选框＋固定底部操作栏”和“题目/参考答案/错因/知识点”白色卡片，不沿用会员弹窗或遮挡试卷的提示。原生当前大量系统 Form/List 与 Demo 有明显差异，不能称为已还原。

建议先让用户审阅选题页和答案整理页的原型，再逐屏落实原生。其他页面继续沿用 V2.4 已确认流程；不在本轮变更删除条件、状态口径和出卷序号。

## 验收边界

本轮能验证的是手动选框交互规则、领域/存储回归和编译。新增自动分题、拍答案、整页匹配和卡片改版均未实现，也没有 API Key 或真实服务请求。后续需用虚构试卷测单栏/双栏、公式/图形、相同题号、网络失败、取消重试、重复保存、学生卷答案泄漏、迁移与备份，再在真机验收。
