# 自动分题多选 Demo 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 在现有 HTML Demo 中交付自动分题后点击加号、多选、改框、补框和批量保存的可操作评审流程。

**Architecture:** 沿用本地 HTML 构建链及 V2.4 领域规则，新增独立收题扩展及样式。仅使用公开虚构题目的预置分题结果，不上传、不调用 API、不假装验证识别准确率。

**Tech Stack:** 原生 JavaScript/CSS、Node 测试、现有独立 HTML 构建器。

**Spec:** `docs/capture-answer-proposal.md` 的收题流程；用户已明确要求参照视频点加号多选，并于 2026-11-09 授权开始。答案照片、AI 解题和原生接口联调属于后续阶段。

## 约束与范围

- 保留 iOS 15.5 原生路线、蓝色主题、删除/历史/打印规则。
- 评审样例明确显示模拟。进入示例直接展示预置候选框；实际 App 仍需主动触发并确认上传。
- 整页画布与固定底栏；点击加号选择/取消，不重复添加。编辑模式才拖动边框，避免选题与移动冲突。
- 补框从四道样例中恢复漏掉的候选；合并保留每个片段及来源，不改变纸面内容。此限制写在界面中。
- 回到选题后再进入分类，保留仍选题目的分类编辑；保存后清空选题和分类草稿，重复保存不重复写入。
- 不声称本轮提高了真实 OCR 准确率，不需要用户提供密钥。
