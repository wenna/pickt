# 拾题：技术栈复核与实现方案

日期：2026-10-22。依据：主设计文档与 HTML Demo V2.4。本文件记录原生开发方案，不表示原生工程或识别能力已经实现。

## 结论

主技术栈不需要更换。继续采用 **SwiftUI + UIKit + Core Data + 本地图片文件 + VisionKit/Vision + 系统 PDF/打印**，最低部署版本固定为 iOS 15.5，无强制登录和自建后端。

需要调整的是实现结构和验证顺序：原方案的框架选型足够，但不足以直接约束 V2.4 中的批量删除、草稿恢复、结果历史、不可变卷快照和多条件筛选。不能把 Demo 的 JavaScript 全局数据直接移植成一个大型 ViewModel，也不能把 HTML 装进 WKWebView 就视为完成原生版。

## 保留与细化

| 范围 | 复核决定 | 原生实现约束 |
| --- | --- | --- |
| 页面与蓝色主题 | 保留 SwiftUI，UIKit 封装复杂系统界面 | 颜色统一管理，列表批量操作栏保持可访问；字体放大、安全区域及主要触控区域做真机检查 |
| 页面状态 | 采用小型 MVVM 与明确的页面状态 | 使用 iOS 15.5 可用的 ObservableObject/状态绑定；导航封装可回退，不无条件使用仅新系统可用 API |
| 图片扫描与编辑 | 保留 VisionKit、UIKit 画布、Core Image | 普通拍照/相册回退；原图保留，方向与裁剪坐标统一，多片段顺序稳定 |
| 元数据与图像 | 保留 Core Data + Application Support 文件 | 显式模型版本、文件标识和引用；大图不进 UserDefaults 或单条数据库字段 |
| 业务一致性 | 增加独立领域服务及持久化接口 | 单题/批量、界面/写入层共用删除规则；写入前重新读取并校验，不信任旧按钮状态 |
| 分类与筛选 | 本地目录和确定性规则先行 | 多知识点/错因关系、历史自填目录、日期区间；同维度 OR、跨维度 AND，按 ID 保留选题 |
| 完成卷批改 | 分为对齐、OCR、建议、人工确认四步 | 不把识字等同判题；正式记录只来自确认流程，无法判定保持待核对 |
| PDF 与打印 | 保留系统渲染、预览、打印和分享 | 同一布局计划用于预览和输出，保存卷面题号与位置；学生页和家长页独立 |
| 可选免费模型 | 保留 URLSession 服务适配层 | 默认关闭；接入时确认免费与能力，不保证数学图片可用，不自动转付费 |
| 构建交付 | 沿用 StudyBuddy 未签名 IPA 路径 | 固定可用工具链配置、明确 App 路径、标注提交号；用户下载后自行重签侧载 |

## 原生模块边界

建议从一个 App target 和一个可测试的业务模块开始，避免首版拆成过多工程：

- **界面层**：错题本、扫描与分类、练一练、批改核对、家长设置；各自 ViewModel 只负责交互与调用业务用例。
- **领域层**：题目与卷状态、删除资格、批量选择、序号分配、快照、批改确认与统计。优先纯 Swift 类型，不依赖 SwiftUI 和 Core Data 托管对象。
- **数据层**：Core Data 持久化、图片资源库、迁移、完整备份/恢复。跨线程传递 ID 或值快照，不传递受上下文约束的托管对象；遵循 [Apple Core Data 后台访问规则](https://developer.apple.com/documentation/coredata/using-core-data-in-the-background)。
- **系统服务层**：扫描、OCR、图像处理、PDF、打印、文件分享、Keychain 和可选模型服务。将不可用、取消和失败明确返回给界面，保留人工回退。

依赖方向是界面调用领域用例，领域通过接口访问数据与系统能力。无需首版引入第三方架构框架、跨平台运行时或云数据库。测试可替换服务实现，业务规则只维护一份。

## 数据与事务是本次必须加强的部分

在主设计实体之外明确区分：知识点/错因目录及多对多关联、批改尝试、批改草稿及逐题草稿、已确认结果事件、练习卷题目快照、卷面版本/布局计划、图片资源引用、出卷序号计数器。

关键约束：

1. **状态派生**：卷有未确认草稿时为待核对；无草稿但有已确认尝试/结果时为已记录；两者皆无才是待完成。题目掌握状态、最近确认结果、待核对提示分开。确认时间相同时用稳定顺序字段作补充排序，不依赖数组位置。
2. **批量删除**：在统一串行写入入口读取最新数据，先检查整批，再在同一持久化事务写入全部软删除标记；任何一项失败则不保存并回滚。相关批改/结果写入也经过该入口，防止“校验后、保存前”插入新状态。不使用绕过条件的数据库批量硬删除。
3. **确认入库**：以唯一尝试 ID 去重，原子保存整卷尝试、逐题结果和需要更新的掌握状态，并结束对应草稿。重复点击不新增次数；未做同样保留事件，但不计有效练习。
4. **序号**：新建卷与递增计数器在同一事务提交，失败不占号；跨科目共用，改名、打印、删除恢复不改变原序号。
5. **历史快照**：卷引用保存时的题目内容和答案版本；题库编辑/软删除不回写旧卷。旧结果不能因目录项改名、移入回收站或恢复而消失。
6. **图片与数据库**：文件系统和数据库没有一笔共同事务。采用临时文件 → 完整写入并校验 → 移到正式位置 → 保存数据库引用；中断后清理孤立临时资源，不能先创建悬空引用。备份包含被历史卷和回收站引用的文件。
7. **草稿与后台任务**：每次关键核对操作后持久化，不能只依赖应用退出时保存。扫描和 OCR 限制并发、可取消/重试；不承诺 iOS 会在 App 退出后继续完成整卷识别。

## 完成卷识别：增加卷面身份与布局版本

以下布局持久化是本轮明确的原生技术要求；当前 HTML Demo 尚未实现布局版本保存与真实照片匹配。

“拍了做完的卷”需要知道是哪份卷、哪一版排版、哪一页、哪一道题。只保存题号或一张照片不足以可靠对应答案。

- 生成 PDF 时保存 `paperID`、`layoutRevision`、页码、题目快照 ID、题目及答题区的位置；卷面打印可读的短卷号和页码，内部使用完整标识。可选二维码只是辅助匹配，不作为首版必须依赖。
- 改题序或留白会改变位置，重新生成时新增布局版本，保留已输出版本。最初拍完成卷时由用户从对应练习卷进入；版本无法可靠识别时让用户选择，不能静默用最新布局套旧卷。
- 每次尝试绑定布局版本并保存照片、透视校正及题号对应结果。缺页、重复页、匹配不确定时进入待核对；允许人工指定题目/作答区域。
- 开始批改后冻结该尝试使用的快照和布局。重新打印已有布局不影响状态；需要新的排版时另存布局版本，不修改旧尝试的依据。
- 原题以图像为准用于重印；本地 OCR 用于辅助搜索、分类与作答读取，不能靠普通文字识别可靠恢复复杂公式或批改过程分。

本地判定先限定为参考答案已由家长确认、输入可确定解析的数值或选择题。数值、分数与单位只在显式支持的类型内规范化比较，不用浮点字符串相等草率判断；语义、证明、过程和模糊字迹交给人工确认。该分层是工程方案，不是已验证的准确率承诺。

## iOS 15.5 兼容性

导航采用支持旧系统的封装；`NavigationStack` 不能无条件用于 iOS 15.5，可基于旧导航或系统版本分支。Apple 的[导航迁移说明](https://developer.apple.com/documentation/swiftui/migrating-to-new-navigation-types)明确给出了旧系统兼容路径。

OCR 使用兼容路径 `VNRecognizeTextRequest`；不将新的 `RecognizeTextRequest` 作为首版依赖。[Apple Vision 文档](https://developer.apple.com/documentation/vision)说明新版 Swift API 从 iOS 18 起提供。语言支持按运行时查询，并使用适配测试样本，不把最新系统的表现推断到 iOS 15.5。

使用 Core Data，不将 SwiftData 或仅新系统可用的 Observation 框架作为核心依赖。Swift 编译器版本与 iOS 部署目标分别管理；依赖库的最低系统要求也必须核查。CI 编译成功不代表已经在 iOS 15.5 运行成功；以 [Apple Xcode 支持表](https://developer.apple.com/xcode/system-requirements)分别核对部署、设备调试和模拟器条件，不要求 CI 必须提供 iOS 15.5 模拟器。

## 免费模型与自动批改边界

不新增必需的云端后端、不内置共享密钥，也不为了开放式自动判题而强制接入免费平台。免费额度、视觉输入、题型能力和服务稳定性需要接入当时另行核实；没有免费且可用的视觉/推理能力，就提供本地整理与人工核对，不伪造已自动完成。

模型返回只作为待审核建议；密钥放 Keychain，不进入日志、备份或 Git。默认只处理已核对的单题文本；需要传图时明确显示实际发送的裁剪内容。首版自动分类可以采用本地目录、关键词及用户默认值，标注建议来源，不依赖数学理解模型才可保存题目。

## GitHub 构建：复用交付方式，调整可追溯性

本轮只读检查了本机 StudyBuddy 的 `.github/workflows/ios-unsigned-ipa.yml`：现有流程是手动触发、macOS runner、禁用代码签名构建 iPhone App、放入 `Payload` 并打包未签名 IPA，再上传 artifact。没有运行或修改 StudyBuddy 的工作流。

拾题沿用该链路，正式开发时改进以下约束：

- 首轮从当前镜像列表挑选实际可用的 macOS runner 与 Xcode 组合，明确写入配置并输出版本。避免长期只依赖漂移的 `macos-latest`；镜像也会更新，固定标签不是永久固定环境，应记录变更并复验。[GitHub runner 镜像清单](https://github.com/actions/runner-images)、[Apple Xcode 支持表](https://developer.apple.com/xcode/system-requirements)。
- 明确本项目名、共享 scheme、稳定 Bundle ID 和 `IPHONEOS_DEPLOYMENT_TARGET=15.5`；依赖版本锁定。编译号由专用版本规则产生，与应用内练习卷序号完全无关。
- 先测试业务规则和持久化，再编译 `iphoneos` 设备产物；按确定的产物路径取 App，禁止找到任意首个 `.app` 就当作交付结果。
- IPA 文件名及同包清单含应用版本、编译号、Git 提交号、工具链及 SHA-256 校验值；将最低系统版本与二进制设置核对后上传。使用 [GitHub artifact](https://docs.github.com/en/actions/concepts/workflows-and-actions/workflow-artifacts) 下载，不把 IPA 和证书放进 Git。
- 检查所需动态库与资源均在包中，不误用模拟器产物。CI 不需要开发者证书；用户下载后由侧载工具重签。未签名 IPA 是打包形式，不是未签名直接运行能力。
- GitHub 仓库地址、Actions 权限和可用额度在实际推送前确认。本轮没有创建原生工程、设置远程地址、推送代码或触发构建。

## 建议实施顺序与验收

1. 先建立原生骨架、主题与领域测试，把三类状态、序号、删除策略和过滤选择落实；创建最小可构建 App 后就接通 macOS CI，及早暴露工具链问题。
2. 实现 Core Data、图片库、迁移和完整备份；验证批量失败不部分保存、重复确认不重复记数、恢复不丢草稿。
3. 实现扫描、框选、多片段、分类、错因与原题组卷。分数和几何图直接保留图像，保证打印可读。
4. 实现统一 PDF 布局、版本与打印；验证学生/家长页分纸、留白、缺页及长题。
5. 实现完成卷匹配、本地 OCR 与核对草稿；先用已确认答案的小范围题型验证判定，其他回退人工。
6. 最后评估可选免费模型。自动识别和判定未达到可用性前，不阻塞已完成的本地闭环。

当前 JavaScript 检查继续作为交互参考；原生实现须另写真正的领域与 Core Data 集成测试，并验证文件损坏、迁移、应用中断、大图内存、iOS 15.5 与较新系统真机、侧载覆盖更新和实物打印。不得把 Demo 的通过数直接当作原生测试成绩。

## 2026-10-26 框选交互修复

新增 CropInteraction 纯 Swift 交互会话，统一命中、移动、八方向缩放、归一化图内约束，UIKit 将 44 点手柄触控区转换为图片坐标，按手势初始快照计算。画布图像身份不变时不重置缩放；拖动中不接受 SwiftUI 的旧选区覆盖，取消恢复原框。

工程版本 0.1.1 / build 2；Debug 单独启用 DEBUG 条件，CI 可用虚构试卷预览蓝框与手柄，Release 不含该入口或样例。新增文件后运行 python3 scripts/generate_project.py；CI 继续执行 swift test 与设备/模拟器编译，并额外生成 crop-preview.png。原生触控验收不能由静态图片代替。自动分题与答案方案的官方核验及未完成项见 ../docs/capture-answer-proposal.md。
